# 상세페이지 카피 사전 검수기 (copy_lint)

렌더 단계 **앞에서** 돌려서, 고객에게 나가면 안 되는 문장과 산출물을 잡는 린터입니다.
표준 라이브러리만 쓰므로 설치할 게 없습니다 (Python 3.8+).

```
qa/
├── copy_lint.py     검수 엔진 + CLI
├── rules.json       검수 규칙 (문구 사전, 임계값)
├── test_lint.py     회귀 테스트
└── sample/
    ├── rendered_regulatory_mat.json   실제 산출물 문구(결함 포함) - FAIL 케이스
    ├── clean_example.json             교정 카피 - PASS 케이스
    └── report.json                    리포트 JSON 예시
```

---

## 1. 실행

```bash
# 카피만 검수
python qa/copy_lint.py --copy copy.json

# 렌더된 이미지까지 검수 + 리포트 저장
python qa/copy_lint.py --copy copy.json --images-dir ./output --json-out report.json

# P0가 있으면 종료코드 1 (CI/스크립트에서 렌더 중단)
python qa/copy_lint.py --copy copy.json --images-dir ./output --strict
```

입력은 **JSON** 또는 **카피.md** 둘 다 됩니다.

```jsonc
// JSON (권장 - 파이프라인 연동용)
{
  "product_name": "무압박 수면양말 4종세트",
  "review_count": 0,
  "sections": [
    {
      "id": "S1", "name": "히어로", "label": "무압박 수면양말",
      "headline": ["겨울밤 발목을", "조이지 않는", "수면양말"],
      "description": "발목을 감싸는 넓은 파일 밴드",
      "points": [{"key": "밴드", "text": "넓게 짠 파일 조직이 압력을 나눠 받습니다"}],
      "tiles": ["4켤레", "45g", "225~250mm"]
    }
  ]
}
```

```
# 카피.md (지금 쓰는 형식 그대로 파싱됨)
## 1. S1 히어로
**라벨:** 규조토 발매트
**대제목:** 아이 샤워 후
**설명:** ...
**핵심 포인트:**
- **아이동선** 욕실 앞 젖은 발 아래 배치
**아이콘 타일:** 52×32 · 1kg
```

종료 코드: `0` P0 없음 · `1` P0 발견 · `2` 입력 오류

## 2. 파이프라인에 끼우기

```python
from qa.copy_lint import lint, print_report, RenderBlocked

payload = build_copy_dict(job)          # 지금 쓰는 product JSON
report = lint(payload, images_dir=job.out_dir, rules_path="qa/rules.json")

if report["blocked"]:                    # P0가 하나라도 있으면
    print_report(report)
    raise RenderBlocked(report)          # 렌더/발행 중단

render(payload)                          # P1/P2는 경고만 남기고 진행
```

- **P0 = 차단**. 고객에게 나가면 법적·신뢰 리스크가 생기는 것.
- **P1 = 경고**. 전환에 손해지만 치명적이지 않은 것. 정책상 강행 가능.
- **P2 = 참고**. 중복·용량·구성 같은 품질 항목.

리포트 JSON에는 `blocked`, `verdict`, `counts`, `issues[{rule,severity,section,quote,field,message,fix}]`가 담깁니다.
그대로 검수 화면에 뿌리면 됩니다.

## 3. 규칙 목록

| 규칙 | 등급 | 잡는 것 | 판정 방식 |
|---|---|---|---|
| L001 | P0 | 기획/제작 메모가 고객 카피로 노출 | "배치 연출", "사용 컷", "제품명에", "상세 표기" 등 문구 매칭 |
| L002 | P1 | 서술어 없이 제작 용어로 끝나는 문장 | 문장 끝이 표기/연출/장면/컷/구도/위치/기준/확인 |
| L003 | P0 | 오타 | 사전 매칭 (사워→샤워, 발으면→받으면, 안전적인→안전한 등) |
| L004 | P0 | 근거 없는 효과 주장 | 순간 흡수·빠른 건조·항균·먼지 최소화 등 + 문서 내 시험/인증 근거 없음 |
| L005 | P1 | 절대 표현 | 100%·완벽·완전·절대·전혀 |
| L006 | P0 | 소재 이중 주장 | "100%" + 복수 소재 동시 등장 |
| L007 | P0 | 비교 대상 오류 | "일반 상세페이지", "타사 상세" 등 제품이 아닌 대상 |
| L008 | P0/P1 | 상품정보 고시 누락 | 고시 섹션 없음 / 필수 항목(재질·크기·제조국·A/S 등) 누락 |
| L009 | P0 | 고시에 "상세페이지 참조" | 실제 값이 아닌 회피 표기 |
| L010 | P1 | 배송/교환/반품 실값 누락 | 배송비·반품·교환 미기재 |
| L011 | P1 | 조건 회피 문구 | "주문 전 확인", "판매 조건 기준" 등 |
| L012 | P0 | 리뷰 0건인데 후기 라벨 | review_count=0 + "후기/리뷰/구매평" |
| L013 | P2 | 헤드라인 없음 / 줄 수 초과 | 4줄 초과 |
| L014 | P1 | 결론 없는 헤드라인 | 마지막 줄이 ~면/~라면/~때/~경우로 끝남 |
| L015 | P1 | 섹션 간 내용 중복 | 문자 2-gram 유사도 0.62 이상 |
| L016 | P2 | 아이콘 타일 세트 반복 | 같은 타일 조합이 3개 섹션 이상 |
| L017 | P1 | 상품명 단어 반복 | "무압박 남녀공용 무압박" 같은 중복 |
| L018 | P1 | 가격 정보 없음 | 문서 내 "원" 표기 없음 |
| L019 | P1 | 이미지 1장 용량 초과 | 기본 1MB |
| L020 | P2 | 동일 이미지 중복 | MD5 해시 동일 |
| L021 | P1 | 산출물 총 용량 초과 | 기본 3MB |
| L022 | P2 | 종횡비 제각각 | 3가지 이상 |
| L023 | P0 | 섹션 제목 렌더 버그 | 제목 앞에 라벨 글자 1자가 붙은 형태 |
| L024 | P0 | 필수 섹션 누락 | 히어로 / 배송·교환 |

임계값은 `rules.json`의 `limits`에서 바꿉니다.

---

## 4. 규칙 늘리는 법

`rules.json`은 데이터만 고치면 됩니다. 코드는 건드리지 않습니다.

```jsonc
{
  "typos": { "몇일": "며칠" },                       // 오타 추가
  "planning_phrases": ["보여주는 컷"],                 // 기획 메모 문구 추가
  "claims": ["정전기 방지", "냄새 없"],                // 효과 주장 추가
  "evidence_markers": ["시험성적서 번호"],             // 근거로 인정할 표기
  "invalid_comparison_targets": ["타 브랜드"]          // 비교 대상 금지어
}
```

새 상품군이 생기면 그 카테고리에서 실제로 문제 된 문장을 `claims`, `planning_phrases`에 계속 넣는 방식으로 키우면 됩니다.

## 5. 테스트

```bash
python qa/test_lint.py
```

- 실제 산출물(규조토 발매트) → 알려진 결함 9종을 모두 잡고 FAIL 판정
- 교정 카피(`clean_example.json`) → P0 0건, PASS 판정 (오탐 없음)
- `카피.md` 파서 → 8섹션 파싱 확인

---

## 6. 한계 (알고 쓰기)

1. **문맥 이해가 아니라 사전 매칭**입니다. 새로운 표현의 효과 주장은 사전에 넣기 전까지 못 잡습니다.
2. **맞춤법 전체 검사가 아닙니다.** 자주 틀리는 단어 사전 방식이라, 없는 오타는 통과합니다.
3. **이미지 내용은 보지 않습니다.** 용량·중복·비율만 봅니다. 사진이 카피와 맞는지는 사람이 봐야 합니다.
4. 따라서 **린터는 최소 기준선**입니다. P0 0건이 "좋은 상세"를 뜻하지는 않습니다.

| 대상 | 섹션 | 이미지 | P0 | P1 | 판정 |
|---|---|---|---|---|---|
| 규조토 발매트 (렌더 실제 문구) | 8 | 8장 18.33MB | 20 | 16 | **FAIL** |
| 같은 상품 카피.md | 8 | - | 8 | 13 | **FAIL** |
| 교정 카피(clean_example) | 4 | - | 0 | 0 | **PASS** |

카피.md는 통과 문장이 많지만(오타·효과 주장 없음), **렌더 결과에는 오타 6건과 효과 주장 4건이 새로 생겼습니다.**
즉 지금 파이프라인은 카피 원본과 렌더 결과가 다른 경로를 타고 있으므로, 검수는 **렌더 직전(렌더 입력)** 과 **렌더 직후(산출물)** 두 번 도는 것이 안전합니다.
